# Telegram IPA Signing Bot (personal-certificate workflow)

A small Telegram webhook bot that signs an IPA using the uploader's own `.p12` and
matching `.mobileprovision` file, using the open-source `zsign` command-line tool.

## Important limitations

- This is a hobby/demo deployment, not a guaranteed 24/7 service.
- Render free web services sleep after 15 minutes without inbound traffic and
  have ephemeral filesystems. A sleeping service can take about a minute to wake.
- Telegram's hosted Bot API currently limits bot file downloads to 20 MB. This
  project therefore rejects input files over 20 MB. Output upload is capped at 50 MB.
- The bot keeps the current job state in RAM. A restart/sleep/redeploy can cancel
  an in-progress job; users must start again with `/sign`.
- The bot handles one active job per Telegram chat.
- The `.p12` and provisioning profile are uploaded to the hosting provider while
  signing. They are stored only in a temporary job folder and removed after success,
  failure, or `/cancel`; platform logs should never include certificate passwords.
- Do not use certificates you do not own or have permission to use. Never share
  your `.p12` password with anyone. Telegram messages are not an ideal secret vault.
- A valid signature does not guarantee installation: certificate type, profile,
  app entitlements, bundle identifier, device UDID registration, expiry and Apple's
  trust/revocation rules all matter.

## 1. Create a Telegram bot

1. Open Telegram and chat with `@BotFather`.
2. Send `/newbot`, follow the prompts, and copy the bot token.
3. Keep the token private. If exposed, revoke it with BotFather.

## 2. Create a GitHub repository

1. Create a new repository on GitHub, e.g. `telegram-ipa-signing-bot`.
2. Upload all files from this folder to the repository root.
3. Do not upload your `.p12`, `.pfx`, `.mobileprovision`, IPA, or `.env` files.

## 3. Deploy to Render free

1. Sign in to Render and choose **New → Blueprint**.
2. Connect the GitHub repository containing `render.yaml`.
3. Review and create the service using the **Free** plan.
4. In the service's **Environment** settings, add `BOT_TOKEN` with your BotFather token.
   `WEBHOOK_SECRET` is generated by the blueprint; if it is not, set a long random
   value yourself. Do not publish it.
5. Deploy. Wait for the build to finish. The Docker build compiles `zsign`.
6. Copy the service's public `onrender.com` URL if you want to test the health page.
   Opening it should show `IPA Signing Bot is running`.

The app registers its Telegram webhook automatically when the service starts and
`RENDER_EXTERNAL_URL` is available.

## 4. Use from iPhone

1. Open your bot in Telegram and tap Start.
2. Send `/sign`.
3. Upload your own `.p12` or `.pfx`.
4. Upload the matching `.mobileprovision`.
5. Upload the IPA (maximum 20 MB).
6. Send the `.p12` password when asked.
7. If signing succeeds, the bot returns `signed.ipa`. Tap it and use the iPhone
   Files/Share sheet to save it.

Use `/cancel` to abandon a job. Use `/sign` to start a new one.

## Troubleshooting

- **No response:** open the Render service URL once to wake a sleeping service,
  then retry `/start`. Check Render logs and confirm `BOT_TOKEN` and
  `WEBHOOK_SECRET` are set.
- **Wrong password:** re-enter the password by starting a fresh `/sign` job.
- **Signing fails:** check that the p12 contains the private key, password is correct,
  provisioning profile matches the signing certificate and app identifier, and
  required devices are included in the profile.
- **Build fails:** inspect Render build logs. `zsign` is built from its upstream
  source; upstream build dependencies or build instructions can change.

## Security notes

This is a minimal starter implementation. For public multi-user production use,
add authentication/allowlists, per-user rate limits, durable job queues, encrypted
object storage, automatic secret rotation, and stronger isolation. Do not put
certificate files or passwords in GitHub, source code, Render environment values,
or issue trackers.
